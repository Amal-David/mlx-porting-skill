Evidence before deployment

Apple Silicon inference engines

Reviewed 2026-10-05. 24 pinned projects and 14 method contracts. This is not a performance leaderboard. No third-party engine was benchmarked in this survey.

MLX-VLM remains the multimodal reference; serving layers, native specialized runtimes and non-MLX comparators solve different problems. Expand a project for its scope and limitations.

BaseRT · opaque-engine

A separately benchmarkable engine with public tooling and integration materials.

Limit: The Apache-licensed repository does not make the inference engine open source; inspect license boundaries before reuse and do not claim access to its kernels.

Runtime: Proprietary runtime; public integration tools. Workloads: interactive, coding-agent.

Pinned primary source · Local validation: not run.

dflash-mlx · speculation-adapter

DFlash draft/verify adapter plus server, recurrent tape-replay rollback, hot/cold prefix snapshots and verification-specialized kernels.

Limit: Greedy target verification is not identical to stochastic exact sampling; dispatch differences can alter the AR path. Sparse prefill is a separate approximate feature.

Runtime: Python / MLX / Metal. Workloads: coding-agent, interactive, specialized.

Pinned primary source · Local validation: not run.

exo · distributed-runtime

Topology-aware sharding across devices, including tensor/pipeline approaches and transport-dependent placement.

Limit: Capacity across Macs is not a single-Mac latency win. Link bandwidth, collective cost and failure recovery are part of the benchmark.

Runtime: Python / MLX and distributed transports. Workloads: distributed.

Pinned primary source · Local validation: not run.

Flash-MoE · non-mlx-specialized

Active-expert streaming from SSD for a large sparse model on a smaller-memory Mac.

Limit: Not MLX and not generic dense-model offload. No root license was found in the pinned inventory; do not copy code pending permission. SSD streaming does not remove OOM risk.

Runtime: C / Objective-C / direct Metal. Workloads: specialized.

Pinned primary source · Local validation: not run.

llama.cpp · non-mlx-comparator

Mature non-MLX comparator with GGUF, native Metal and serving workflows.

Limit: GGUF quantization and MLX quantization may not encode identical weights; report the artifact/quality difference rather than an engine-only ratio.

Runtime: C/C++ / GGML / Metal. Workloads: interactive, coding-agent, multi-user, multimodal.

Pinned primary source · Local validation: not run.

mistral.rs · non-mlx-comparator

Rust inference with continuous batching, multimodal prefix handling and per-layer quantization/device mapping.

Limit: Metal support is not MLX support. Do not transfer CUDA-specific kernel or paged-attention measurements to Apple hardware.

Runtime: Rust / Candle / Metal. Workloads: interactive, multi-user, multimodal, embeddings.

Pinned primary source · Local validation: not run.

MLC LLM · non-mlx-comparator

Compiler-driven deployment with a shared runtime and prefix-cache machinery across supported platforms.

Limit: Ahead-of-time compilation/build cost and format conversion belong in deployment comparisons; this is not an MLX backend.

Runtime: TVM / compiled device runtimes. Workloads: interactive, multi-user.

Pinned primary source · Local validation: not run.

Methods and required gates

P0 · phase-metrics

Separate process/load, request first-content latency, physical prefill, cached tokens, decode and end-to-end time; disclose observed model width.

Correctness: Monotonic parent timing; valid token accounting; no heartbeat counted as a token; preserve failure rows.

Measure: Cold/warm/partial-prefix runs, p50/p95 latency, aggregate throughput, RSS/Metal/cache/swap separately.

Rollback: Reject comparison or keep baseline when artifact, workload, precision, hardware or metric semantics differ.

P0 · memory-admission

Reserve model plus projected KV/state/activation growth and system headroom before admission; bound queues and eviction.

Correctness: Mixed long/short overload, pinned-model constraints, cancellation releases leases, rejected requests produce explicit errors.

Measure: Peak and steady memory, queue time, admission failures, eviction stalls, tail latency.

Rollback: Reduce admission or unload safely; never silently reduce context or quantize weights.

P0 · packaged-runtime

Pin the entire executable/dependency/native-library environment and probe the actual compiled backend capabilities.

Correctness: Relocatable environment launch, correct ABI/library resolution, no ambient packages; first real workload inside the intended isolation.

Measure: Cold load, warm load, compiler/startup work, packaging size and selected/fallback kernel counters.

Rollback: Refuse unsupported ABI/device paths and keep a tested runtime; do not broaden sandbox permissions to hide failures.

P0 · protocol-conformance

Test exact tool/reasoning/template, usage, stop, cancellation and error semantics with versioned client transcripts.

Correctness: Malformed tools fail; unsupported controls fail explicitly; disconnect halts work; no hidden template/sampling change.

Measure: First-content latency, successful tool round trips, stream errors and cancellation cleanup.

Rollback: Fall back to a declared supported route or return an explicit unsupported error.

P1 · stateful-cache

Use topology-specific immutable checkpoints, copy-on-write and leases; recurrent state cannot be reconstructed by slicing ordinary KV.

Correctness: Cold-vs-warm next-token/logit and multi-turn checks; exact prefix length; rollback; tenant and adapter/media identity mutation tests.

Measure: Exact and partial hit rates, restored versus computed tokens, clone bytes and restoration cost.

Rollback: Invalidate incompatible/corrupt state and recompute; never reuse partially qualified hybrid state.

P1 · chunked-prefill

Token-budget chunking interleaves prefill and decoding; continuous batching must expose actual compute widths and safe per-request state.

Correctness: Unequal lengths, left padding/masks, per-request sampler/stop, cancellation at chunk boundaries, no starvation.

Measure: Prefill versus decode latency, p95 inter-token time, observed width, queue depth and aggregate tokens.

Rollback: Reduce chunk/concurrency budget or revert to single-request execution when quality or tail latency regresses.

P1 · media-identity

Separate encoder-output and language-state caches; bind media content and processor/frame/audio settings to exact cache identity.

Correctness: Same text with changed image/audio/frame order must miss; processor/template/adapter/tenant changes invalidate.

Measure: Encoder latency, media bytes, prompt prefill, first-audio and first-text boundaries separately.

Rollback: Disable the media cache and re-encode when identity or restored-state qualification is missing.

P2 · tiered-cache

Bound hot RAM and cold SSD stores with explicit format/version, checksums, atomic writes and per-namespace limits.

Correctness: Interrupted write/restart, checksum failure, partial restore, lease/eviction races, no cross-tenant hits.

Measure: SSD reads/writes, restore latency, physical and apparent prefill rates, hot/cold hits and resident state.

Rollback: Evict or ignore bad snapshots and recompute; keep model-weight fit and SSD-cache capacity as separate budgets.

P2 · speculation

Pair exact target/draft artifacts; optimize the verification shape, track acceptance and retain ordinary decode as a selectable baseline.

Correctness: Greedy and sampled paths separately; residual correction where sampling is claimed; rejected-token KV/GDN rollback; repeated seed/distribution checks.

Measure: Accepted tokens per verification, draft/verify/rollback time, depth, context and short-output break-even.

Rollback: Disable speculation when total useful progress is slower or any target-quality/state gate fails.

P2 · paged-kernels

Use variable-length paged attention and shape/device-specialized fused kernels behind explicit capability guards and a readable reference.

Correctness: Dtype/layout/mask/group-size/length boundary parity; packaged metallib/ABI checks; safe fallback for unsupported shapes.

Measure: Per-phase kernel/launch time, command-buffer/synchronization cost, prefill/decode/verify separately.

Rollback: Revert the exact kernel path on parity, unsupported hardware, allocation or tail-latency regression.

P2 · approximation-gates

Treat KV/weight quantization, expert reduction, sparse prefill and context compaction as separate task-quality experiments.

Correctness: Full model/task metrics and long-context tests; distinguish packed resident storage from a codec with a full-precision shadow.

Measure: Actual resident bytes including shadows/scales, quality deltas and phase timing at the same output policy.

Rollback: Restore precision/expert count/context path if the predeclared task-quality threshold fails.

P3 · expert-streaming

Stream only required expert/table data, overlap bounded I/O, and preserve exact router selections.

Correctness: Match resident execution token/logit/router results; cold SSD stalls and disk failure must fail safely.

Measure: SSD bandwidth, page faults, cold/warm expert locality, resident buffers and sustained decode.

Rollback: Use a smaller model or resident path when I/O stalls or memory headroom fails; never claim streaming eliminates OOM risk.

P3 · topology-routing

Choose tensor versus pipeline partitioning from measured compute/link budgets rather than aggregate RAM alone.

Correctness: Shard identity, full-model parity, rank failure/recovery and collective synchronization.

Measure: Per-rank time, link latency/bandwidth, serial and concurrent latency, total energy and cost.

Rollback: Return to a validated smaller topology or single-host model when communication dominates.

P1 · audio-metrics

Treat speech as a pipeline: frontend, acoustic model, codec/vocoder, chunk flush and playback lead time.

Correctness: WER/CER where appropriate, speaker/prosody fidelity, continuity across chunks, cancellation and long-form drift.

Measure: First-audio latency; real-time factor defined as compute seconds divided by generated audio seconds; peak memory and underruns.

Rollback: Keep the prior audio pipeline if task or continuity gates regress even when text generation speeds improve.
