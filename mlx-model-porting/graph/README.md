# Evidence graph (schema v2)

The machine-readable knowledge layer. `SKILL.md`, the runbooks, and the v1
assets under `assets/` remain the human layer; this directory holds the same
kind of knowledge in a form a tool can query, validate, and merge across
models, hardware, and contributors.

The schema is shared with the `auto-mlx` tool repository.
`schema/evidence-graph.schema.json` is a copy of
`src/auto_mlx/schemas/evidence_graph.json` in that repository; **auto-mlx owns
it**. When it changes upstream, re-copy it and run the validator:
`tools/_graphlib.py` cross-checks every enumeration and required-field list
against the copied file and fails loudly on drift rather than silently
accepting a stale contract.

The array caps (at most 64 `evidence` entries, at least 1; at most 64 `tags`;
at most 32 `identity` properties) are expressed in the JSON Schema and compared
against `tools/_graphlib.py` by the drift check, so neither side can move them
alone.

To cross-check a document against the tool itself:

```bash
cd <auto-mlx checkout>
PYTHONPATH=src python3 -m auto_mlx validate graph --input <file>
```

That validator accepts one self-contained document, so only the **compiled**
graph passes its dangling-reference check. Individual shards carrying
cross-shard edge references fail there on closure alone; resolving those is this
repository's validator's job. `tests/test_evidence_graph_contract.py` asserts
that compilation is lossless, so one check of the compiled graph covers every
node and edge of every shard.

## One command

```bash
python3 mlx-model-porting/graph/tools/validate_graph.py
```

That validates every shard, the cross-shard structure, and the compiled graph,
and fails if the compiled graph is stale. The same checks run from
`tests/test_evidence_graph_contract.py` under the repository's normal
`python3 -m unittest discover -s tests`.

## Layout

```
graph/
  schema/evidence-graph.schema.json   upstream contract, copied from auto-mlx
  shards/                             authored + generated JSON graph shards
    core/                             hardware, workloads, cross-cutting constraints
    models/                           model nodes and their exhibits edges
    mechanisms/                       mechanism nodes and their applies_to edges
    campaigns/<campaign>/             results, findings, hypotheses, references
    ecosystem/                        third-party reported results
    migrated/                         GENERATED by tools/migrate_v1.py
  compiled/evidence-graph.json        GENERATED by tools/compile_graph.py
  MECHANISM_INDEX.md                  GENERATED by tools/render_graph_summary.py
  packs/                              contributed evidence packs (see docs/)
  docs/evidence-packs.md              the contribution format
  tools/                              stdlib-only Python, no third-party imports
```

Each shard is itself a complete, schema-valid graph document, not a fragment.
That means a consumer can load one shard without the compiler, and it means a
shard can be validated in isolation. Edges may reference nodes declared in any
other shard; the validator resolves them across the whole corpus.

## Invariants

The validator enforces all of these. Several go beyond what JSON Schema can
express.

**Strict integer JSON.** No floats anywhere, including inside `identity` and
`effect`. Parsing rejects a float literal before any other check runs. Effects
are integer basis points: `-257` means `-2.57%`. This exists so that two
independent tools agree on every stored number byte for byte.

Also rejected at parse time: `NaN` / `Infinity`, duplicate object keys, and
unpaired surrogates.

**Node ids name their kind.** `mechanism:...`, `trait:...`, `result:...` for
`applied_result`, `external:...` for `external_reference`, and so on.

**Edges are typed at both ends.** `exhibits` is model to trait, `applies_to` is
mechanism to trait, `instantiates` is applied_result to mechanism,
`applied_on`/`measured_on`/`under_workload` are applied_result to
model/hardware/workload, `transfer_predicted` is mechanism to model, and
`confirms`/`refutes` are applied_result to mechanism or hypothesis.

**The hyperedge must be complete.** Every `applied_result` carries an `effect`
and has exactly one `applied_on`, one `measured_on`, and one `under_workload`
edge, plus at least one `instantiates`. A measurement with no hardware or no
workload is not a measurement anybody can reuse, so the graph will not store
one. Conversely, `effect` may appear *only* on an `applied_result`.

**A claimed sign must be unambiguous.** `effect.metric_direction`
(`higher_is_better` / `lower_is_better`) is optional in the schema, but every
`applied_result` in this repository declares it. When it is present, an
`improved` or `regressed` verdict requires the whole interval to sit strictly on
the claimed side of zero. An interval that touches or straddles zero does not
support a sign — that is what `inconclusive` is for. Every metric in this corpus
is higher-is-better, so a sign error cannot hide behind an ambiguous metric name.

**Evidence is mandatory and public.** Every node needs at least one locator,
and no locator, summary, or identity value may contain an absolute local path
(`/Users/...`, `/home/...`) or anything shaped like a credential. Use a URL or
a descriptive locator such as `qwen38 campaign promotion ledger, PROMOTION_LEDGER.md`.

**Generated output is byte-stable.** Sorted keys, nodes sorted by id, edges
sorted by `(from, relation, to)`, LF endings, UTF-8. `generated_at` on the
compiled graph is the newest shard's `generated_at`, never the wall clock, so
regenerating without an input change rewrites identical bytes.

## Reading an effect honestly

`delta_bp_ci` is an interval, but it is not automatically a confidence
interval. When a result comes from a single scored run, the interval is the
point `[x, x]` and `sample_note` says so. When it comes from repeated pairs,
the interval spans the observed pairs and `sample_note` says how they were
collected.

`verdict` is deliberately conservative. For the Qwen 3.8 campaign, three
official runs of byte-identical candidate content scored 130 basis points
apart (`finding:official-rerun-variation`). Every campaign result whose delta
falls inside that spread is recorded as `inconclusive`, even where the campaign
itself retired the candidate. The campaign's decision to stop spending
submissions on it was correct; the number alone did not establish harm, and the
graph records what the number supports. Node `status` carries the human
decision; `effect.verdict` carries the measurement.

## Regenerating

```bash
python3 mlx-model-porting/graph/tools/migrate_v1.py          # shards/migrated/
python3 mlx-model-porting/graph/tools/compile_graph.py       # compiled/
python3 mlx-model-porting/graph/tools/render_graph_summary.py # MECHANISM_INDEX.md
python3 mlx-model-porting/graph/tools/validate_graph.py
```

Run them in that order. `--check` on the compiler and the renderer verifies the
checked-in output without writing, which is what CI uses.
